# Editor API

`editor-api` — отдельный Quart-сервис на порту `8081`. Он владеет проектами кухни, определениями мебели, неизменяемыми ревизиями, библиотекой, экземплярами, каталогом и миграционным журналом. `user-service` хранит только пользователей, сессии и профильные данные.

## Авторизация

Браузер отправляет обычную cookie сессии. `editor-api` пересылает только заголовок `Cookie` в `GET /api/auth/me` пользовательского сервиса и получает подтверждённый `user_id`. При недоступности auth-сервиса запрос закрывается ответом `503`; отсутствие сессии даёт `401`, неподходящая роль — `403`. Cookie не записывается в журнал.

## Основные ресурсы

- `/api/editor/definitions` — постоянная идентичность цельного мебельного элемента;
- `/api/editor/definitions/:id/revisions` — неизменяемые версии JSON-документа;
- `/api/editor/revisions/:id` — чтение конкретной ревизии;
- `/api/editor/library` — ссылки библиотеки на определения;
- `/api/editor/kitchens` — помещение и метаданные проекта кухни;
- `/api/editor/kitchens/:id/instances` — размещённые ссылки на конкретные ревизии;
- `/revision-preview` и `/revision` у экземпляра — безопасный предпросмотр и явное обновление;
- `/api/editor/catalog/*` — версионируемый каталог без встроенных вымышленных данных брендов.

Сохранение существующего определения требует `basedOnRevisionId`. Если базовая версия устарела, API возвращает `409 stale_base_revision`. Доступ к чужому объекту маскируется ответом `404`.

## Развёртывание

Сервис использует только `EDITOR_DB_*`; база может находиться на другом PostgreSQL-сервере. Между `mebel_editor` и пользовательской БД нет внешних ключей. Локально схема применяется идемпотентно при запуске, Docker Compose поднимает отдельный контейнер `editor-postgres`.
