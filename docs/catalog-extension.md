# Расширение каталога и правил

Каталог отделяет продукт от его версии: `catalog_products` хранит постоянную идентичность, а `catalog_product_versions` — артикул и проверенные параметры конкретной версии. Документ мебели ссылается именно на version UUID, поэтому изменение будущего ассортимента не меняет старые проекты. Аналогично устроены материалы.

Новый производитель добавляется только из подтверждённого источника. Рекомендуемый порядок:

1. создать производителя и семейство продукта;
2. добавить неизменяемую версию продукта и артикул;
3. добавить монтажный шаблон с операциями в локальных координатах панели;
4. зарегистрировать независимое правило совместимости в `RuleEngine`;
5. покрыть правило примерами допустимой и запрещённой конфигурации;
6. только после этого разрешить версию для новых проектов.

Правило возвращает `ruleId`, стабильный `code`, `severity`, `entityIds` и параметры. Ошибка блокирует операцию, предупреждение показывается пользователю. Правила не должны проверять строки вроде `bottom`, `side` или `hdf-4` в UI-коде — типы и версии передаются через предметный документ.

Производственные операции содержат UUID панели, локальную грань/координаты, размеры и `source` с происхождением шаблона или ручного действия. Данные бренда, размеры сверления и совместимость нельзя добавлять по предположению.
