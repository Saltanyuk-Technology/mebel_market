# Перенос данных редактора

Источник задаётся через `DB_*`, отдельная целевая база — через `EDITOR_DB_*`. Миграция только читает источник, сохраняет UUID, владельцев, связи с кухней, автосохранения, время создания/обновления, помещение, сцену и библиотечные записи.

Из `services/editor-service`:

```powershell
python -m api.migrate_legacy --dry-run
python -m api.migrate_legacy
python -m api.migrate_legacy --verify-only
```

Для одного проекта используется `--source-project-id UUID`. В `migration_runs` хранится результат запуска, в `migrated_records` — нормализованная SHA-256 сумма каждой исходной записи. Повторный запуск не создаёт новые ревизии или экземпляры для неизменившихся записей.

## Проверки перед отключением старого хранилища

1. `--verify-only` возвращает `valid: true`, без missing/changed.
2. Повторный перенос возвращает `inserted: 0`.
3. Кабинет, редактор и конструктор читают данные через `/api/editor/*`.
4. В `user-service` не зарегистрированы legacy endpoints мебели и библиотеки и не запускается создание их схем.

Старые таблицы намеренно не удаляются автоматически: это безопасная резервная копия на период эксплуатации. Откат приложения выполняется возвратом прежней версии кода; исходные строки миграция не меняет. Удалять старые таблицы следует отдельной административной операцией только после резервного копирования и подтверждённого периода работы.
